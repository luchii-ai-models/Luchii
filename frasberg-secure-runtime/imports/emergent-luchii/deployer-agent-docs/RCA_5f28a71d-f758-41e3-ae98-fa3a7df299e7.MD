# RCA — run 5f28a71d-f758-41e3-ae98-fa3a7df299e7 (ai-gateway-demo)

## Outcome
Deploy FAILED at `deploy_k8s` (rollout never became ready). Root cause is a **missing application source file**, not a K8s/infra or manifest problem. The previous run (`1113d02a…`, Sep 13) is still live and serving — a failed run is never promoted.

## Failure chain (from the failing run's rollout logs)
1. Image built and pod scheduled fine; nginx came up on :8080.
2. Backend (uvicorn) crashed on import: `GET /health` → `connect() failed (111: Connection refused)` to `127.0.0.1:8001`; entrypoint then logs `Backend died, shutting down nginx...`.
3. Pod never becomes ready → `deployment failed to become ready: timeout waiting for the condition`.
4. Terminating error:
```
ModuleNotFoundError: No module named 'voice_engine'
  File "/app/backend/server.py", line 33, in <module>
    import voice_engine
```

## Root cause
`backend/voice_engine.py` is **absent from the deployed source**. In the pulled source tree only the compiled bytecode survives:
- Present: `backend/__pycache__/voice_engine.cpython-311.pyc`
- Missing: `backend/voice_engine.py`  ← the actual module

`server.py:33` (`import voice_engine`) and `mesh_ws.py:22` (`import voice_engine`) both require it, so the backend dies at module load. The `.py` was deleted/lost in the preview environment; the leftover `.pyc` in `__pycache__` is why the symbol history is still recoverable. There is no `.dockerignore`/`.gitignore` excluding it and the tree is not a git repo, so this is a genuine missing file, not an exclude rule. Run 1113d02a succeeded on Sep 13 because the file still existed then; it was removed before this redeploy.

## Verification (in eph sandbox, failing run's source)
- Reproduced: with the source as-pulled, `import voice_engine` raises `ModuleNotFoundError` — identical to production.
- Confirmed cause: dropping a `voice_engine.py` into `backend/` makes `import voice_engine` succeed; boot then advances past line 33 to the expected DB/secret boundary (no secrets in sandbox — out of scope, and not a code fault).

## Fix (apply in the SOURCE / preview environment, then redeploy)
Restore `backend/voice_engine.py`. Best options, in order:
1. Recover from your editor/checkpoint/version history (the file existed at the Sep 13 deploy).
2. Decompile the surviving bytecode `backend/__pycache__/voice_engine.cpython-311.pyc` (Python 3.11) to reconstruct the original.

The restored module MUST expose the public API the app calls (extracted from the `.pyc` and from usages in `server.py`/`mesh_ws.py`):
- Data: `VOICES` (list of `{"name","id",...}`), `VOICE_IDS`
- Functions: `status()`, `transcribe(raw, suffix)`, `speak(text, tone, voice)`, `clone_speak(text, sample_path)`, `convert_to_wav(raw, path)`, `preload_sync()`, `preload_xtts_sync()`, `_mem_available_gb()`
- (Internal helpers seen in bytecode: `_load_whisper/_load_tts/_load_xtts`, `_encode_wav`, `_try_recover`, model-name constants `WHISPER_MODEL/COQUI_MODEL/XTTS_MODEL`.)

Do NOT ship a stub in place of the real module — it would silently disable transcription/TTS/voice-cloning. The stub was used only to prove the import is the blocker.
