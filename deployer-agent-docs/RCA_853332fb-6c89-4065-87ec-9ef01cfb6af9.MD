### Why the upstream gateway is NOT rescuing chat (root of the 100% rate)
Code flow (server.py):
- `_env_upstream = os.environ.get("LUCHII_UPSTREAM_URL")`; `UPSTREAM_CANDIDATES = [_env_upstream]`.
- `_probe_upstreams()` (60s loop) sets `ACTIVE_UPSTREAM = url` ONLY if `{root}/v1/health` (or root) returns status `< 400`. 403/404/timeout/unreachable ⇒ `ACTIVE_UPSTREAM = None`.
- Chat (`server.py:511-516`): `_try_upstream(...)` returns `None` immediately when `ACTIVE_UPSTREAM` is falsy (`server.py:126`), so it never calls the gateway and falls straight to the EMERGENT_LLM_KEY litellm branch.
- NET: the Frasberg gateway at LUCHII_UPSTREAM_URL is NOT passing the health probe (not live / returning ≥400 / unreachable), so 100% of chats fall back to the inactive EMERGENT_LLM_KEY → turbulence. This matches the user's expected root cause: stale universal key with no *working* upstream.
